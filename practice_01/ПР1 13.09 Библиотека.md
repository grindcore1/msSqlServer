# ПР1 13.09 - Мини-проект «Электронная библиотека»

- **Предметная область:** электронная библиотека (книги, авторы, жанры, читатели, выдачи)
- **СУБД:** Microsoft SQL Server 2025 (SSMS 22)
- **База данных:** LibraryDB
- **Срок:** 13.09

## 1. Постановка задачи

Разработать структуру БД «Электронная библиотека» для хранения данных о книгах, авторах, жанрах, читателях и выдачах. База позволяет хранить список книг с авторами и жанрами, учитывать, какие книги и когда выданы, фиксировать возврат и видеть активных читателей. База, таблицы, ключи, ограничения, данные и диаграмма созданы через графический интерфейс SSMS.

## 2. Сущности и атрибуты

**Genres (Жанры)**

| Атрибут | Тип | Ограничения |
|---|---|---|
| GenreID | int | PK, IDENTITY(1,1) |
| GenreName | nvarchar(50) | NOT NULL, UNIQUE |
| Description | nvarchar(200) | NULL |

**Authors (Авторы)**

| Атрибут | Тип | Ограничения |
|---|---|---|
| AuthorID | int | PK, IDENTITY(1,1) |
| FullName | nvarchar(100) | NOT NULL |
| Country | nvarchar(50) | NULL |
| BirthYear | int | NULL |

**Books (Книги)**

| Атрибут | Тип | Ограничения |
|---|---|---|
| BookID | int | PK, IDENTITY(1,1) |
| Title | nvarchar(200) | NOT NULL |
| AuthorID | int | NOT NULL, FK -> Authors |
| GenreID | int | NOT NULL, FK -> Genres |
| PublishYear | int | NULL |
| ISBN | nvarchar(20) | NOT NULL, UNIQUE |
| CopiesTotal | int | NOT NULL |

**Readers (Читатели)**

| Атрибут | Тип | Ограничения |
|---|---|---|
| ReaderID | int | PK, IDENTITY(1,1) |
| FullName | nvarchar(100) | NOT NULL |
| Phone | nvarchar(20) | NULL |
| Email | nvarchar(100) | NULL |
| RegistrationDate | date | NOT NULL |
| IsActive | bit | NOT NULL, DEFAULT 1 |

**Loans (Выдачи)**

| Атрибут | Тип | Ограничения |
|---|---|---|
| LoanID | int | PK, IDENTITY(1,1) |
| BookID | int | NOT NULL, FK -> Books |
| ReaderID | int | NOT NULL, FK -> Readers |
| LoanDate | date | NOT NULL |
| DueDate | date | NOT NULL, CHECK (DueDate >= LoanDate) |
| ReturnDate | date | NULL (NULL - книга ещё у читателя) |

## 3. Нормализация

**Исходная таблица с нарушениями**

| Книга | Авторы | Жанр | Читатель | Телефон читателя | Дата выдачи |
|---|---|---|---|---|---|
| Война и мир | Лев Толстой, Россия | Роман | Иван Петров | +7-901-111-11-11 | 01.09.2026 |
| Война и мир | Лев Толстой, Россия | Роман | Мария Сидорова | +7-902-222-22-22 | 03.09.2026 |

Проблемы: в одном поле хранится несколько значений (автор и страна), данные о книге и авторе повторяются в каждой выдаче, телефон читателя повторяется во всех его выдачах. Из-за этого возникают аномалии: при изменении телефона его нужно менять во многих строках (аномалия обновления), нельзя добавить книгу, которую ещё никто не брал (аномалия вставки), при удалении последней выдачи пропадают сведения о книге (аномалия удаления).

- **1NF:** все поля атомарные - автор и страна разнесены по отдельным столбцам, у каждой строки есть ключ.
- **2NF:** данные, зависящие только от части ключа (книга, читатель), вынесены в отдельные таблицы Books и Readers, в выдаче остались только ключи и даты.
- **3NF:** убраны транзитивные зависимости - страна зависит от автора, а не от книги, поэтому вынесена в Authors, название жанра - в Genres.

В итоге получились таблицы Authors, Genres, Books, Readers, Loans, в которых каждый факт хранится один раз.

## 5. Проектирование базы данных

Скриншот 17. Диаграмма базы данных LibraryDiagram

![[библиотека_09.png]]

Связи:

- Authors - Books: 1:N (у автора много книг, у книги один автор).
- Genres - Books: 1:N (в жанре много книг).
- Readers - Loans: 1:N (читатель может брать книги много раз).
- Books - Loans: 1:N (одну книгу выдают многократно).
- Books - Readers: M:N, реализована через таблицу Loans.

## 6. Дополнительные задания

1. **Таблица Genres** создана и связана с Books через FK_Books_Genres (скриншоты 2, 3, 8).
2. **Тестовые данные** - по 5 строк в каждой таблице (скриншоты 12-16).
3. **Схема БД** - диаграмма LibraryDiagram (скриншот 17).
4. **Отчёты для библиотекаря:**
   - Список книг, находящихся у читателей: название, читатель, дата выдачи и срок возврата (выдачи без ReturnDate).
   - Просроченные выдачи: книги, у которых срок возврата прошёл, а книга не возвращена, с телефоном читателя.
   - Активные читатели и количество взятых ими книг за месяц.
   - Популярность жанров: сколько раз выдавали книги каждого жанра.

## Приложение. Скрипт, эквивалентный действиям в интерфейсе

```sql
CREATE DATABASE LibraryDB;
GO
USE LibraryDB;
GO
CREATE TABLE dbo.Genres (
    GenreID     INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Genres PRIMARY KEY,
    GenreName   NVARCHAR(50)  NOT NULL CONSTRAINT UQ_Genres_GenreName UNIQUE,
    Description NVARCHAR(200) NULL
);

CREATE TABLE dbo.Authors (
    AuthorID  INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Authors PRIMARY KEY,
    FullName  NVARCHAR(100) NOT NULL,
    Country   NVARCHAR(50)  NULL,
    BirthYear INT NULL
);

CREATE TABLE dbo.Readers (
    ReaderID         INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Readers PRIMARY KEY,
    FullName         NVARCHAR(100) NOT NULL,
    Phone            NVARCHAR(20)  NULL,
    Email            NVARCHAR(100) NULL,
    RegistrationDate DATE NOT NULL,
    IsActive         BIT  NOT NULL CONSTRAINT DF_Readers_IsActive DEFAULT 1
);

CREATE TABLE dbo.Books (
    BookID      INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Books PRIMARY KEY,
    Title       NVARCHAR(200) NOT NULL,
    AuthorID    INT NOT NULL CONSTRAINT FK_Books_Authors REFERENCES dbo.Authors(AuthorID),
    GenreID     INT NOT NULL CONSTRAINT FK_Books_Genres REFERENCES dbo.Genres(GenreID),
    PublishYear INT NULL,
    ISBN        NVARCHAR(20) NOT NULL CONSTRAINT UQ_Books_ISBN UNIQUE,
    CopiesTotal INT NOT NULL
);

CREATE TABLE dbo.Loans (
    LoanID     INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Loans PRIMARY KEY,
    BookID     INT  NOT NULL CONSTRAINT FK_Loans_Books REFERENCES dbo.Books(BookID),
    ReaderID   INT  NOT NULL CONSTRAINT FK_Loans_Readers REFERENCES dbo.Readers(ReaderID),
    LoanDate   DATE NOT NULL,
    DueDate    DATE NOT NULL,
    ReturnDate DATE NULL,
    CONSTRAINT CK_Loans_DueDate CHECK (DueDate >= LoanDate)
);
GO
```

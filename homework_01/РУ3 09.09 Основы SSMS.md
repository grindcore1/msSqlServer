**Ответы на вопросы**

- **Настройки при создании:** имя базы, владелец, логические имена, начальный размер и автоувеличение файлов данных и журнала, путь к файлам, файловые группы, а на странице «Параметры» - параметры сортировки, модель восстановления, уровень совместимости.

**Ответы на вопросы**

- **Типы данных:** nvarchar - для имён и названий (поддерживает кириллицу, длина переменная), int - для идентификаторов, decimal(10, 2) - для зарплаты (точные деньги без ошибок округления float), date - для даты приёма (без лишнего времени).
- **Ключи:** PRIMARY KEY однозначно определяет строку и не допускает повторов и NULL. FOREIGN KEY связывает таблицы и не даёт сослаться на несуществующую запись.
- **Изменение структуры:** добавление столбца с NULL не трогает существующие строки (в новом столбце будет NULL). При удалении столбца его данные теряются. При смене типа данные могут не преобразоваться, и SSMS откажется сохранить изменения.

**Ответы на вопросы**

- **Добавление и изменение:** добавление создаёт новую строку (INSERT), изменение меняет значения в уже существующей строке (UPDATE), ключ строки при этом остаётся тем же.
- **Фильтры и сортировка:** позволяют быстро найти нужные строки и упорядочить их, не просматривая всю таблицу. В конструкторе запроса условия задаются в столбцах «Фильтр» и «Тип сортировки», SSMS сам собирает WHERE и ORDER BY.
- **Связи и данные:** внешний ключ не даёт добавить сотрудника в несуществующий отдел и удалить отдел, в котором есть сотрудники. Благодаря связи можно соединять таблицы и видеть у сотрудника название отдела.

## Приложение. Скрипт, эквивалентный действиям в интерфейсе

```sql
CREATE DATABASE CompanyDB;
GO
USE CompanyDB;
GO
CREATE TABLE dbo.Departments (
    DeptID   INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Departments PRIMARY KEY,
    DeptName NVARCHAR(50) NOT NULL,
    Location NVARCHAR(50) NULL
);

CREATE TABLE dbo.Employees (
    EmpID    INT IDENTITY(1,1) NOT NULL CONSTRAINT PK_Employees PRIMARY KEY,
    FullName NVARCHAR(100)  NOT NULL,
    Salary   DECIMAL(10, 2) NOT NULL,
    HireDate DATE NOT NULL,
    DeptID   INT NULL CONSTRAINT FK_Employees_Departments REFERENCES dbo.Departments(DeptID)
);
GO
ALTER TABLE dbo.Employees ADD Email NVARCHAR(100) NULL;
ALTER TABLE dbo.Employees DROP COLUMN Email;
GO
INSERT dbo.Departments (DeptName, Location) VALUES
(N'Бухгалтерия', N'Москва'),
(N'ИТ-отдел', N'Санкт-Петербург'),
(N'Отдел продаж', N'Казань');

INSERT dbo.Employees (FullName, Salary, HireDate, DeptID) VALUES
(N'Анна Смирнова', 85000, '2024-03-15', 2),
(N'Игорь Волков', 62000, '2023-11-01', 1),
(N'Павел Козлов', 70000, '2025-02-10', 3),
(N'Елена Новикова', 95000, '2022-06-20', 2),
(N'Сергей Морозов', 55000, '2026-01-12', 3);

UPDATE dbo.Employees SET Salary = 65000 WHERE FullName = N'Игорь Волков';

SELECT EmpID, FullName, Salary, HireDate, DeptID
FROM dbo.Employees
WHERE Salary > 60000
ORDER BY Salary DESC;
GO
```
